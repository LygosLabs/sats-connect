# DLC Testing Guide with Fordefi Wallet

This guide walks through testing the complete DLC (Discreet Log Contract) flow using the SatsConnect example app with a Fordefi wallet on Bitcoin Testnet4.

## Overview

The test demonstrates the full DLC lifecycle:
1. **SatsConnect creates offer** - Frontend generates a DLC offer
2. **Backend (DDK) accepts** - Backend accepts the offer using DDK library
3. **Sign** - Wallet signs the accept message
4. **Finalize** - Create final transactions
5. **Broadcast** - Broadcast funding transaction to network
6. **Execute with Oracle** - Execute the DLC using oracle attestation (currently has a known issue)

## Prerequisites

- Node.js (v18+ recommended)
- pnpm (for dlc-backend)
- npm (for example app)
- Fordefi wallet browser extension configured with a Bitcoin Testnet4 vault
- Mobile device with Fordefi app for transaction approvals

## Project Structure

```
sats-connect/
├── dlc-backend/     # Express server with DDK for accepting DLC offers
├── example/         # React frontend for testing SatsConnect
└── src/             # SatsConnect library source
```

## Setup Instructions

### 0. Fund Wallets

Both wallets need Testnet4 BTC to create the DLC:

1. **Fund the DLC Backend wallet** - After starting the backend (step 1), the server logs will show the wallet address. Send at least **100,000 sats** to this address.

2. **Fund your Fordefi Testnet4 vault** - Send at least **100,000 sats** to your Fordefi Bitcoin Testnet4 vault address.

You can get Testnet4 BTC from faucets like:

- <https://mempool.space/testnet4/faucet>

### 1. Start the DLC Backend

```bash
cd dlc-backend
pnpm install
```

**Create a `.env` file** (required):

```bash
cp .env.example .env
```

Edit `.env` with your configuration:

```env
# Bitcoin network - using testnet4 for testing
NETWORK=testnet

# Optional: Provide your own mnemonic (otherwise one will be generated)
# If not provided, a new mnemonic will be auto-generated on each server start
MNEMONIC="your 24 word mnemonic here"

# Server port
PORT=3005
```

**Start the server**:

```bash
pnpm run dev
```

The backend runs on `http://localhost:3005` and uses:

- **Network**: Bitcoin Testnet4
- **API**: mempool.space Testnet4 Esplora API (rate-limited to avoid 429 errors)
- **Wallet**: Uses mnemonic from `.env` (or auto-generates if not provided)

### 2. Start the Example Frontend

In a new terminal:

```bash
cd example
npm install
npm run dev
```

The frontend runs on `http://localhost:5173`

## Testing the DLC Flow

### Step 1: Connect Wallet

1. Open `http://localhost:5173` in your browser
2. Click **"Change Network"** and select **Testnet4**
3. Click **"Connect"** to connect your Fordefi wallet
4. Approve the connection in Fordefi

You should see your connected addresses displayed (payment and ordinals addresses).

### Step 2: Navigate to Bitcoin Methods

1. Click **"Bitcoin Methods"** in the left sidebar
2. Scroll down to find **"Test SatsConnect Provider"** section

### Step 3: Initiate DLC Flow

1. Click **"Test Complete DLC Flow (Offer → Accept → Sign)"**
2. Wait 15-30 seconds for the backend to process

The Fordefi modal will appear showing **5 Transactions**:
- Funding Transaction
- Refund Transaction
- CET #1 (Contract Execution Transaction)
- CET #2
- CET #3

### Step 4: Approve Transactions

1. Click **"Create All"** in the Fordefi modal
2. Open your mobile phone with the Fordefi app
3. Approve the transaction requests

### Step 5: View Results

After approval, scroll down to see the DLC Test Results:

- **DLC Offer Created Successfully** - Shows contract info (collateral, event ID, oracle pubkey)
- **DLC Offer Details** - Contract ID, fee rate, locktimes, funding info
- **DLC Accept Received from Backend** - Accept message from DDK
- **DLC Sign Created Successfully** - Signed message ready for finalization

### Step 6: Finalize DLC

Click **"Finalize DLC"** to create the final transactions.

You'll see:
- **Transaction Finalized!**
- TX ID and raw transaction hex

### Step 7: Broadcast Transaction

Click **"Broadcast Transaction"** to broadcast the funding transaction to the Bitcoin Testnet4 network.

### Step 8: Execute DLC (Known Issue)

Click **"Execute DLC"** to attempt execution using the oracle attestation.

**Expected Error in dlc-backend terminal** (current known issue):

```
Error executing DLC: Error: InvalidSignature
    at BitcoinDdkProvider.FindAndSignCet
    ...
```

This error indicates that adaptor signature support needs to be fixed with Fordefi. The DLC execution step fails because the adaptor signatures generated by Fordefi are not being verified correctly by the DDK library.

## Architecture Notes

### Frontend (example/)
- React + Vite application
- Uses `sats-connect` library to communicate with Fordefi wallet
- Creates DLC offers using `@node-dlc/messaging` and `@atomicfinance/*` packages

### Backend (dlc-backend/)
- Express server on port 3005
- Uses DDK (Discreet Log Contract Development Kit) via `@atomicfinance/bitcoin-ddk-provider`
- Accepts DLC offers and creates accept messages
- Uses mempool.space API for Testnet4 blockchain data

### Key Endpoints

| Endpoint | Description |
|----------|-------------|
| `POST /api/dlc/accept` | Accept a DLC offer, returns accept message |
| `POST /api/dlc/sign` | Process sign message from wallet |
| `POST /api/dlc/finalize` | Finalize DLC transactions |
| `POST /api/dlc/execute` | Execute DLC with oracle attestation |

## Troubleshooting

### Connection Issues
- Ensure Fordefi is configured for Bitcoin Testnet4
- Check that both frontend and backend servers are running

### Transaction Approval Timeout
- The Fordefi modal may take 15-30 seconds to appear
- Ensure mobile app is ready for approval requests

### Rate Limiting
- The backend uses rate-limited API calls to avoid 429 errors from mempool.space
- If you see rate limit errors, wait a moment and retry

### Execute DLC Error
The `InvalidSignature` error during DLC execution is a **known issue** with adaptor signature support in Fordefi. This is the specific bug that needs to be investigated and fixed.
